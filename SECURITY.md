# Security Policy

The security and privacy of our users are of paramount importance. Leaf is designed with privacy-by-design principles: 100% of user financial data is stored locally on the user's device (Android or iOS), with zero telemetry, zero analytics SDKs, and zero proprietary backend servers.

---

## Supported Versions

Only the latest release and the current active development branch are actively supported with security updates:

| Platform | Active Version Series | Supported |
| :--- | :--- | :--- |
| **Android** | `1.1.x` | :white_check_mark: |
| **Android** | `< 1.1.0` | :x: |
| **iOS** | `1.0.x` | :white_check_mark: |
| **iOS** | `< 1.0.0` | :x: |

---

## Reporting a Vulnerability

If you discover a potential security vulnerability, cryptographic weakness, unintended data exposure, or authentication bypass in Leaf, please **do NOT** open a public issue or discuss the issue publicly.

Instead, please report it privately through one of the following channels:

1. **GitHub Security Advisory (Preferred):**
   - Navigate to the repository's **Security** tab on GitHub.
   - Click **Report a vulnerability** to submit a private draft advisory.

2. **Direct Responsible Disclosure:**
   - Contact the maintainer privately with details regarding the vulnerability, reproduction steps, affected platform (Android or iOS), and potential impact.

---

## Disclosure Process & Response

- **Acknowledgment:** We will acknowledge receipt of your vulnerability report within 48 hours.
- **Remediation:** We will work with you to analyze, reproduce, and remediate the issue promptly.
- **Release & Credit:** Once a fix is verified, a patched release will be published alongside a security advisory acknowledging your responsible disclosure (unless you prefer to remain anonymous).

Thank you for helping keep Leaf secure and private for everyone!
